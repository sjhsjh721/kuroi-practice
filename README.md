# 쿠로이 연습실 PWA

설치 링크: **https://sjhsjh721.github.io/kuroi-practice/**

악보·대본과 자동 시간표·배역 형광 좌표를 사용하는 설치형 웹앱입니다. 원본 92개 음원과 PDF 18개를 보존하고, 웹앱용 MR+화음 58개는 정렬을 보정하고 음량을 분리한 파일로 제공합니다. 기존 Android·iOS 프로젝트는 변경하지 않습니다.

## 설치와 오프라인 연습

1. iPhone·iPad에서 배포 링크를 Safari로 열고 공유 → 홈 화면에 추가 → 웹 앱으로 열기를 선택합니다. Android에서는 Chrome의 앱 설치 또는 홈 화면에 추가를 사용합니다.
2. 추가한 아이콘에서 앱을 열고 자기 배역을 선택합니다. 멀티배역도 함께 표시합니다.
3. 상단 다운로드에서 전체 자료(약 570MB), 내 배역+공통 음원, 현재 넘버 중 선택합니다. 정확한 용량은 패널에 표시됩니다. 앱을 열어 둔 상태에서 저장 완료를 확인합니다.
4. 저장 완료 후 네트워크 없이 다시 열고 재생할 수 있습니다. 일시정지한 다운로드는 이어받을 수 있으며, 이미 저장된 파일은 다시 받지 않습니다.

전체 다운로드는 필수가 아닙니다. 인터넷이 연결돼 있으면 자료를 미리 받지 않고도 열고 재생할 수 있습니다. 오프라인에서 연습할 범위만 골라 저장하면 됩니다.

첫 배역 선택 후 용량과 함께 내 배역 자료 저장을 권장합니다. ‘다운로드’를 누르면 내 배역+공통 음원을 저장하고, ‘나중에’를 누르면 안내를 닫고 바로 연습합니다. 닫은 안내는 다시 표시하지 않으며, 상단 다운로드에서 언제든 저장할 수 있습니다.

0.8.3으로 업데이트할 때 기존 다운로드의 SHA-256이 같은 파일은 이전 캐시에서 재사용합니다. 이전 MR+화음을 받아 둔 경우 보정 자료 저장 안내가 한 번 나타납니다. 같은 다운로드 범위를 선택하면 새 MR+화음 파일만 추가로 받습니다. 이전 파일별 재생 위치와 보정·숨김 기록도 새 파일로 연결하며, 내 메모 대본은 별도 기기 저장소에 유지합니다.

홈 화면 추가와 자료 다운로드는 별개입니다. 홈 화면에 추가한 웹앱에서 자료를 다운로드하세요. 저장 공간 부족이나 웹사이트 데이터 삭제로 자료가 지워지면 다시 받아야 합니다. 지속 저장을 요청하지만 브라우저의 허용을 보장하지 않습니다. 자료 삭제는 보정 기록을 지우지 않습니다.

## 연습 기능

- MR·AR·배역 화음·MR+화음 자동 정렬 미리듣기, 0.5~1.25배속과 음량
- MR+화음 선택 후 재생기 옆 음량 아이콘에서 MR·화음·전체 음량을 각각 조절하고 기억
- 악보·대본 자동 넘김, 악보 0~5초 미리 넘김, 음표·마디 터치 재생
- 양쪽·대본·악보 보기와 전체화면, 전체화면 재생바·이전/다음 넘버
- 좌우 스와이프·페이지 버튼·번호 입력으로 수동 넘김, 두 손가락 확대·이동, 두 번 탭 화면 맞춤
- 내 메모 대본 PDF로 바꿔 보기, 기기 저장·오프라인 복원, 원본과 전환
- 구간 반복, ±5초 탐색, 파일별 마지막 재생 위치, 배역 기억
- 현재 지점 보정, 자동 지점 숨김, 지점 탐색·삭제, 자동 시간표 복원
- Android·iOS 호환 JSON 보정 백업 내보내기·가져오기. 웹 확장 필드로 숨김 기록도 보존
- 기본 알림창 대신 화면 안의 컴팩트 패널, 공식 Lucide 아이콘과 짧은 라벨

앱을 벗어나거나 화면을 잠그면 재생을 멈춥니다. PWA의 전체화면은 화면 안의 조작부를 유지하며 문서를 넓힙니다. 브라우저 전체화면 API가 지원되는 환경에서는 함께 사용하고, iPhone에서는 홈 화면 설치 모드를 사용합니다.

대본·악보를 왼쪽으로 밀면 다음 장, 오른쪽으로 밀면 이전 장으로 이동합니다. 양쪽 보기에서는 손댄 문서만 넘깁니다. 확대 중 한 손가락 드래그는 문서를 이동하며, 화면 맞춤 후 스와이프로 넘길 수 있습니다. 직접 페이지를 넘기면 자동 넘김을 멈춥니다. 하단 ‘자동/수동’ 버튼으로 전환하며, 자동을 다시 켜면 현재 음원 시점의 페이지로 돌아갑니다. 이 동작은 전체화면과 한쪽 보기에서도 같습니다.

확대·이동 후 현재 보이는 영역을 PDF에서 기기 해상도에 맞춰 다시 그립니다. 확대하는 동안에는 기본 페이지를 유지하고, 동작이 잠시 멈추면 선명한 영역으로 교체합니다. 전체 페이지를 거대한 이미지로 만들지 않아 태블릿의 최대 확대에서도 캔버스 메모리 사용을 제한합니다.

대본 왼쪽 위의 펜 아이콘 또는 연습 도구 → 내 메모 대본 → PDF 선택에서 필기한 대본을 고릅니다. 자동 넘김·배역 표시 좌표를 그대로 사용하므로 원본과 같은 79쪽의 순서·배치를 유지한 PDF(50MB 이하)를 사용하세요. PDF의 Ink 주석도 표시합니다. 선택한 파일은 서버로 올리지 않고 이 브라우저의 IndexedDB에 저장해 오프라인에서 복원합니다. ‘원본 대본 사용’으로 전환해도 내 파일을 보관하므로 다시 선택할 수 있습니다. 앱 내에서 PDF를 편집하는 기능은 포함하지 않습니다. 기기 간 자동 전송하지 않으며, 브라우저 데이터 삭제 시 원본 파일을 다시 선택해야 합니다.

자동 페이지 전환은 기존 추정 시간표를 사용합니다. MR+화음은 악보 박자와 AR에서 인식한 가사 시점을 기준으로 다시 정렬하고 음의 시작 특징으로 세부 위치를 맞춥니다. 사람이 전곡을 청취해 타이밍을 승인한 자료는 아니며, 일부 구간에는 추정 오차가 남습니다.

MR+화음은 모노 반주와 모노 가이드를 한 파일의 두 채널에 나눠 담고, 앱에서 각 음량을 조절해 중앙으로 합쳐 재생합니다. 한 재생 시계를 사용하므로 재생바·배속·반복 조작에서 두 소리가 따로 움직이지 않습니다. 원음 MR·AR의 일반 재생은 기존 스테레오 경로를 사용합니다. 합산 시 드문 피크는 공통 버스에서 완만하게 제한합니다.

## 개발·배포

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm preview
pnpm test
# 공개 배포 주소의 같은 시나리오 검증
PWA_BASE_URL=https://sjhsjh721.github.io/kuroi-practice/ pnpm test
```

일반 HTTPS 정적 호스팅에 `dist/`를 올립니다. Service Worker는 HTTPS 또는 localhost에서만 동작합니다. 경로는 루트와 GitHub Pages의 하위 경로를 모두 지원합니다. 별도 서버·DB·유료 Apple 개발자 계정은 필요하지 않습니다.

공개 배포는 GitHub Pages를 사용합니다. 최초 Sites 전송에서는 소스 Git과 256MiB 배포 묶음 한도에 걸려 전체 자료를 배포하지 못했습니다. `.openai/hosting.json`의 기존 Sites 식별자는 복구 기록으로 보존하며 Sites에 성공한 배포는 없습니다. 원본 자료와 음질을 유지하기 위해 GitHub Release에 검증된 `dist/` 묶음과 SHA-256을 올리고 `.github/workflows/pages.yml`에서 묶음 검증 후 Pages로 배포합니다. 무료 공개 Pages의 사이트 1GB 한도 안에 들며, 월 100GB 소프트 트래픽 한도는 별도로 적용됩니다. Cloudflare Pages 계정이 있으면 같은 `dist/`를 직접 올릴 수도 있습니다.

`scripts/prepare_library.py`는 Native 원본과 생성한 MR+화음을 복사하고 SHA-256 목록을 만듭니다. 현재 다운로드 목록은 `public/library-manifest-v2.json`, 새 합성 음원은 `library/mixes/v2/`, 목록은 `mix-catalog-v2.json`을 사용합니다. 원본 114개 자료는 바이트가 같습니다. 구 버전 앱이 열려 있어도 잘못된 채널을 재생하지 않도록 기존 목록·파일·URL도 호스팅에 보존하되 새 다운로드 범위에는 넣지 않습니다. 전체 호스팅 크기는 1GB 미만이며, 새 앱의 오프라인 자료는 약 570MB입니다.

`public/library/`는 Git에 넣지 않고 두 버전 해시 목록을 추적합니다. 독립 체크아웃에서는 검증된 배포 묶음의 `dist/library/`를 `public/library/`로 복사한 뒤 빌드합니다. 누락·변경 파일이 있으면 빌드를 중단합니다. `pnpm-lock.yaml`로 웹 의존성을 고정합니다.

음원 재생성에는 Python 3.14, ffmpeg, Rubber Band 4.0.0이 필요합니다. `scripts/sync-inputs.json`에는 기존 악보·가사 정렬에서 추출한 숫자 시점·음표와 이전 혼합 파일의 기준 자료가 있습니다. 가사 원문은 포함하지 않습니다. [Sync Toolbox](https://github.com/groupmm/synctoolbox)의 chroma/DLNCO와 MrMsDTW로 AR·MR의 시간축을 연결하며, 가사 시점 일부는 적합에서 제외해 별도 검사합니다. [Rubber Band의 오프라인 시간 맵](https://www.breakfastquay.com/rubberband/code-doc/classRubberBand_1_1RubberBandStretcher.html)을 적용하되, 실제 마커·음정·출력 길이 시험에서 확인한 R2/crisp5를 사용합니다.

```sh
uv venv --python 3.14 .venv-audio
uv pip install --python .venv-audio/bin/python -r scripts/audio-requirements.lock
.venv-audio/bin/python scripts/build_split_mixes.py --workers 2
pnpm build
.venv-audio/bin/python scripts/verify_split_mixes.py
```

분석 캐시는 Native 저장소 문맥에서는 상위 `data/sync-v2/`, 독립 체크아웃에서는 `data/sync-v2/`에 둡니다. 원본 음원 또는 정렬 입력이 바뀌면 관련 분석 캐시를 다시 생성해야 합니다. 파형 처리 방식을 바꿀 때는 `RENDER_VERSION`을 올립니다. 원본·구 버전 혼합 파일을 덮어쓰지 않습니다.

보정과 마지막 위치는 기기별 로컬 저장소에 있으며 기기 간 자동 동기화하지 않습니다. 자료는 버전별 CacheStorage에 저장합니다. 전체 파일의 크기·SHA-256을 검증한 뒤 기록하며, 오프라인 오디오는 Service Worker가 Range 요청에 206 응답을 만듭니다. 스트리밍으로 받은 부분 파일을 전체 다운로드로 계산하지 않습니다.

0.8.3의 검사는 실제 출력 음원의 반주 채널을 원본 MR과 대조해 앞·중간·끝의 시계 차이를 측정하고, 두 채널의 게이트 음량을 비교합니다. 브라우저에서는 서로 다른 주파수의 스테레오 신호를 실제 재생해 MR/화음 개별 음소거, 음량 조절 중 재생 지속, 피크 제한, 일반 MR 경로, 설정·이전 보정 백업의 보존을 검사합니다. 별도 가사 시점 검사는 ASR 기반 자동 근거이며 인간의 음악적 정답을 대신하지 않습니다. 짧은 16번 해웅 파트에는 제외해 검증할 가사 시점이 없습니다.

58개 출력 파일 검사에서 MR의 다섯 지점 시계 차이는 0ms, 두 채널의 구간 게이트 음량 차이는 최대 0.1 LU였습니다. 정렬에서 제외한 818개 가사 시점의 절대 오차 중앙값은 기존 4.10초에서 0.315초, 90백분위는 23.82초에서 1.159초로 줄었습니다. 제외 구간의 최대 오차는 17.792초로, 모든 구간의 정확한 음악적 일치를 보장하는 결과는 아닙니다. 실제 제작에는 전체 기준 시점을 사용합니다. 합성 신호의 비선형 시간 변경 검사에서는 440Hz 음정을 유지했고, 네 마커의 최대 시점 오차는 12.9ms였습니다.

## 검증

`?verification`은 연습 설정만 별도 키에 격리하고 자동 검사 인터페이스를 활성화합니다. 실제 연습 기록 키를 덮어쓰지 않습니다. Playwright의 독립 컨텍스트에서 WebKit iPad·iPhone과 Chromium 일반 폰을 검사합니다. 이는 실제 iPad의 홈 화면 설치·잠금·기기 저장 정책을 검증한 것과 구별합니다. 결과는 상위 `artifacts/pwa-*.json`에 보존합니다.

`tests/`는 전곡 시간표 적용, AR 8번 마디 경계 회귀, 실제 악보 터치, 화면 모드·넘버 이동·구간 반복·보정, PDF 241쪽 렌더링, 전체 다운로드 후 네트워크 차단·재실행, 음원 150개 중간 탐색·재생 시계, 다운로드 중단·이어받기와 Native 백업 왕복을 검사합니다.

0.8.2는 확대·이동 후 글자 해상도, 오프라인 재그리기, 페이지 전환 시 이전 확대 영역 제거, 형광 오버레이와 초기 다운로드 안내의 선택·건너뛰기 기억을 추가 검사합니다. Chromium에서는 터치 이벤트로 핀치 확대를 보내며, 모바일 WebKit에서는 Playwright의 네이티브 핀치 제약 때문에 DOM 휠 이벤트로 같은 확대 처리기를 검사합니다. 실제 iOS 기기 제스처 검증과 구별합니다. 배포 시 앱 셸 해시를 Service Worker에 넣어 기존 설치 앱도 새 버전을 감지하고, 자료 캐시는 유지합니다.
